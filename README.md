# Murray Insights: frame-level possession for More than a Hack 2027

Team Murray Insights' entry to the Initial Challenge of
[More than a Hack 2027](https://github.com/metrica-sports/more-than-a-hack-2027): label every one of the
199,319 tactical-video frames of FC Barcelona vs Athletic Club `H`, `A`, `D` (dead ball) or `X` (no answer).

No match data is in this repository, and none ever was. The licensed bundle is not redistributed (RULES.md,
"The data"): each team gets its own copy from the organisers.

## How it works, in one paragraph

There is no leaderboard, so every model is chosen on a bench built from Metrica's three public sample
games. Their clean tracking is degraded until it looks like the competition's automatic tracking: ball
gaps, noise and track fragments calibrated to the real file's distributions, never to its labels.
Possession truth for the sample games comes from their event data (`docs/sample_gt_rules.md`). A
gradient-boosted model gives per-frame H/A/D probabilities, and a three-state Viterbi with switching costs
turns them into possessions. A second model, not submitted, also fills ball gaps with our own ball detection from the
tactical video. Models are scored with the organiser's own `possession_metrics.py`, leave-one-game-out,
over three seeds, with paired bootstraps.

## Setup

```bash
python3.14 -m venv .venv && .venv/bin/pip install -r requirements.txt
scripts/fetch_external.sh        # organiser repo -> ref/, Metrica sample games -> external/ (pinned, hash-checked)
PYTHONPATH=src .venv/bin/python -m pytest -q
```

The competition bundle goes in `data/` (or point `$MTAH_DATA_DIR` at it), laid out as the organiser's
`data/README.md` describes. Register for the challenge and accept the data terms to get it.

## Reproducing the submission

The submission is generated by an algorithm end to end. Nothing in it is hand-labelled or tied to the
competition match's frames.

**Without video (`gbm_v5_nogap`):**

```bash
PYTHONPATH=src .venv/bin/python -m mtah.models.learned --gt touch --tag gbm5_nogap --workers 6
PYTHONPATH=src .venv/bin/python -m mtah.predict --model gbm_v5_nogap --competition --out runs/submission/MurrayInsights.csv
```

**With the video ball (`gbm_v8n`, not submitted; see Status).** First run the detector, in its own environment
(about 4 hours on 8 CPU cores, needs `ffmpeg`). The detector stack needs Python 3.12. If `python3.12` is not on your PATH, install one
(for example `uv python install 3.12`) and put its full path in place of `python3.12` below:

```bash
python3.12 -m venv ~/.cache/wt-mtah-video/venv && ~/.cache/wt-mtah-video/venv/bin/pip install -r requirements-video.txt
scripts/run_video.sh             # -> runs/video/full/ball_track_soccana_ov.npz
PYTHONPATH=src .venv/bin/python -m mtah.models.learned --gt touch --tag gbm8n --workers 6
PYTHONPATH=src .venv/bin/python -m mtah.predict --model gbm_v8n --competition --out runs/submission/MurrayInsights_gbm_v8n.csv
```

`mtah.predict` runs the organiser's `validate_submission` on what it writes. Detector weights are
downloaded and checked by sha256 (`src/mtah/video/weights.py`).

## Status

- **Submission: `gbm_v5_nogap`** (`MurrayInsights.csv`, SHA-256
  `2a7c130bdf0942833536588831f3d55dfa9eb5dd49e7747485599635fb5f7ef5`), locked on 2026-11-13.
  `gbm_v8n` (`899be8ee...` on our machine) is not submitted and not eligible: its simulated video channel was
  tuned on the detector's track from the provided video, and the organisers' clarification email requires tuned
  parameters to come from external data only.
- `gbm_v5_nogap` rebuilds byte for byte from a fresh clone: README steps, retraining included, 19
  minutes on 6 cores. It also rebuilt byte for byte from a checkout with no `runs/`, with numpy's AVX-512 paths and
  OpenBLAS's AVX-512 kernels disabled (same machine).
- For the record, `gbm_v8n` also rebuilds byte for byte from a fresh clone on our machine: the detector run reproduced its output
  exactly (about 3.8 hours on 8 cores), then retraining and prediction took 16 minutes. Not checked on a
  different CPU. Unpinned, Ultralytics 8.4.202 leaves the device and precision to OpenVINO on Linux x86. It ran in
  32-bit float here; per OpenVINO's documented defaults, other CPUs and GPUs may use lower precision, so the file
  could differ.
